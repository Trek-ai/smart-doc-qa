# 评估备忘：为什么放弃「知源 18」全功能版

- 日期：2026-10-21 ~ 2026-10-23
- 结论：**不作为精简交付的形态，改为抽出内核重做**

## 当时的完整版做了什么

「知源 18」是本项目的上一个版本，功能面很宽：

| 维度 | 做法 | 记录 |
|---|---|---|
| 功能 | 文档问答 + 摘要 + 会议纪要 + 导出 Word/Markdown + 检索调试面板 + 检索评测 + 多会话历史 | 接口达 5 个：`/api/summary`、`/api/minutes`、`/api/export`、`/api/debug/retrieve`、`/api/sample` |
| 检索 | 向量检索（需额外 embedding 服务密钥）+ BM25，RRF 融合 | 用户必须再注册一个平台、配第二把密钥 |
| 依赖 | 额外引入 `docx`（导出）、`lib/embedding`（向量适配器） | 安装体积与失败面变大 |
| 交付约束 | 18 是另一项参赛交付物，PPT / 截图 / 110 项自测全部基于完整功能 | 就地砍功能会让既有材料对不上 |

## 三个不可行点

1. **功能面过宽**：界面与后端接口臃肿，评审要理解的重点被摊薄；
2. **部署门槛高**：向量服务需要第二把密钥，评审零门槛试用做不到；
3. **不能就地砍**：18 已作为另一项目的交付物存在，改它等于毁掉那份材料。

## 决定

不动 18，把它里面**经过实战验证的内核**单独抽出来重做 —— 这就是 20「知简」。
